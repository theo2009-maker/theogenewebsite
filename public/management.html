Your management guide.

A practical guide for TheogeneNiyonzima to launch, manage listings, and handle payments responsibly.

Before accepting buyers: create your administrator account, publish genuine device listings, verify seller payment details, and agree delivery and refund arrangements. Example products on the homepage cannot be purchased.

1. Set up your owner administrator account

  1. Open your project in the Netlify dashboard and go to Identity.
  2. Invite your owner email, accept the invitation, and set a strong password. You can also use an existing confirmed account.
  3. Open that user’s details in Identity and add the admin role. Save the change.
  4. Sign out and back in on the website. Open Owner / Admin to add products, review listings, and manage customer orders.

Only grant administrator access to people you trust. Roles are controlled in Netlify, never in the public signup form. Accounts require email confirmation by default. Configure a production email provider in Identity settings if needed for reliable email delivery.

2. Add and manage devices

  1. Choose Add product. Sign up or sign in.
  2. Enter the device name, category, honest condition, integer RWF price, location, and a description including faults and delivery arrangements.
  3. Provide a public HTTPS photo URL you own. Direct photo uploads are not included in this version. Do not use a private or expiring link.
  4. Add the seller’s MTN MoMo or Airtel Money number and its registered recipient name. These details are shown only in the seller/admin dashboard and to buyers who reserve the device.
  5. Choose Publish product as an administrator to make your product available for customers to purchase. Other sellers choose Submit for review.
  6. Products added by an administrator are published immediately. For listings submitted by other sellers, open Owner / Admin, check the photo, description, price, recipient details, and seller information, then approve or reject it. Approved devices appear in the public catalog.

Each listing represents one device. Edit/resubmit and quantity inventory tools are not included. If a pending listing is incorrect, reject it and have the seller submit a corrected listing. Reserved and sold devices disappear from public search. Search covers the latest 200 available listings.

3. Database: already connected

This hosted website uses Netlify Database (PostgreSQL) with Drizzle ORM. It is provisioned on the first connection. It does not need a manually copied database password or an XAMPP server.

DataWhere it lives
Accounts, passwords, rolesNetlify Identity
Device listings, sellers, prices, review statusPostgreSQL: listings table
Reservations, payment references, order statusPostgreSQL: orders table

The schema is in db/schema.ts. When changing the schema, generate a migration using npx drizzle-kit generate --name describe_your_change. Migrations live in netlify/database/migrations/ and are applied automatically during deployment. Never change a migration that has already been applied, and never put credentials in frontend code.

Use the site’s Netlify database tools to inspect records and configure backups or retention as your business requires. Use My account for approvals and order handling. Payment status changes are checked on the server against the signed-in user’s role and ownership.

4. XAMPP and local development

XAMPP bundles Apache, PHP, and MariaDB. MariaDB is a different database engine from this site’s PostgreSQL database. The deployed site does not use PHP and cannot connect to your laptop’s XAMPP service through localhost.

For this project, install Node.js, run npm install, link to your Netlify project with netlify link, then run netlify dev --port 8889. Open http://localhost:8889. This serves the frontend and emulates the Netlify Functions and Identity integration. Keep all credentials on the server.

You may continue using XAMPP for separate PHP/MySQL learning projects. Copying these files into htdocs only serves static pages; it does not run the marketplace API or connect the hosted database. A PHP/MariaDB edition would require a separate backend, authentication, hosting, and schema migration. It is not a switch or a connection setting for this Netlify edition.

5. MTN and Airtel payments without an API

This is a manual transfer workflow. The site does not trigger USSD sessions, debit wallets, receive payment callbacks, provide escrow, or automatically confirm payment. A website cannot reliably confirm a mobile-money payment without an authorized provider integration.
  1. The buyer signs in and reserves a live device. The server locks the device as reserved and stores its price in the order.
  2. The buyer gets the seller’s registered recipient name, mobile number, payment network, and exact amount in My account. The buyer contacts the seller to agree delivery or collection before payment.
  3. On the matching SIM, the buyer dials *182# for MTN MoMo or *500# for Airtel Money, or uses the operator’s official app. Follow the current transfer menu. Operator menus, fees, and availability may change.
  4. The buyer checks the recipient name shown by the operator and pays directly to the seller. The marketplace does not receive funds.
  5. The buyer submits the transaction reference in My account. The order becomes Payment submitted · awaiting verification.
  6. The seller or administrator independently checks the actual recipient wallet for the full amount and matching reference. Only then choose Review & confirm payment and confirm the receipt checkbox.
  7. The order is marked paid and the listing sold. Arrange delivery or pickup directly.

Never accept a reference, screenshot, SMS, or buyer statement alone as proof of receipt. Never request PINs or OTPs. There are no automated refunds or automated shipping tools. A buyer, seller, or administrator can cancel a reservation only before a reference is submitted. Payment-review disputes need direct contact and resolution with the seller and mobile operator; this version does not record refunds.

6. Day-to-day checklist

  • Review pending listings and reject misleading descriptions or suspicious payment information.
  • Check your actual mobile-money statement before confirming each payment.
  • Follow up on unpaid reservations; they do not automatically expire. Cancel abandoned unpaid reservations from My account to make the device available again.
  • Keep device condition, delivery charges, return arrangements, and seller identity clear before a buyer pays.
  • Use separate admin accounts for staff, strong passwords, and restricted roles. Review account access regularly.
  • Monitor Netlify service limits, database usage, function errors, and Identity email delivery.
